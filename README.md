# リアルタイム脳内メーカー

マイクに向かって話すと、話している内容に合わせて脳内メーカーの中身がその場で入れ替わる。
脳内の構成比は [TypeSafe の Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev)（OpenRouter 経由）だけで決め、音声認識は Mac の中で動く Apple の SpeechAnalyzer、描画は p5.js で行う。

うそこメーカーの「[脳内メーカー](https://maker.usoko.net/nounai/)」に着想を得た非公式のもので、本家とは関係ない。
頭の輪郭は測った基準点に合わせて引き直したもので、本家の画像素材は使っていない。

## 動かす

macOS 26 以降と Xcode 26（Swift 6.2 以降）、Node.js 20 以降が要る。npm の依存パッケージは無い。

```sh
npm run build:stt                          # 音声認識の Swift CLI をビルド（初回だけ）
OPENROUTER_API_KEY=sk-or-v1-... npm start  # http://localhost:8053
```

- 初回はマイクの許可ダイアログが出る。許可する相手は、起動元のターミナルになる
- 日本語の音声モデルが未導入なら、初回に macOS が自動でダウンロードする
- ポートを変えるときは `node server.js 9000`
- マイクなしで試すときは `node server.js --no-stt`。画面の入力欄に文字を打つと、確定した字幕として扱う
- キーはサーバーが環境変数から読み、ブラウザには渡さない

## しくみ

1. `stt/` の Swift CLI がマイクの音声を日本語の字幕にして、stdout へ 1 行 1 JSON で出す。認識途中（interim）と確定（final）を分けて出す
2. `server.js` がそれを読み、SSE（`GET /api/captions`）でブラウザへ流す。Jev への呼び出しも中継する（`POST /api/decisions`）
3. ブラウザは字幕を積み、直近 30 秒かつ 120 文字までを「窓」として切り出す
4. 確定が届いたらすぐ、認識途中は 1.2 秒に 1 回まで、かつ 6 文字以上変わったときだけ、Jev に聞く。同時に飛ばすのは 1 本で、最短でも 1 秒あける
5. 返ってきた 53 字の構成比を、前回の構成比と指数移動平均でならす（新しい答えの重み 0.6）
6. 構成比を最大剰余法で 75 セルぶんの個数に直す。字ごとに決まった種セルがあり、個数の多い字から順に種に近い空きセルを取る。同じ字が塊になる
7. 入れ替わったセルだけを 300ms で切り替える

### Jev への聞き方

エンドポイントは OpenRouter の Decisions（alpha）`POST https://openrouter.ai/api/alpha/decisions`、モデルは `typesafe/jev-1.13`。
Jev は文章を生成せず、`state` と型付きの質問を受け取って確率つきの判断を返す。

`state` には、英語の説明文（`task`）と、日本語のままの字幕を入れる。字幕は 3 つに分け、新しいものを重く見るよう `task` で指示する。

| キー | 中身 |
|---|---|
| `transcript.speaking_now` | 認識途中の字幕（末尾 120 文字まで） |
| `transcript.latest` | 直前に確定した 1 行 |
| `transcript.earlier` | それより前の、窓に入っている行 |

質問は 1 リクエストに 55 問。Jev は全問を並列に評価するので、問いを増やしても応答時間はほとんど変わらない。

| 質問 | 型 | 内容 |
|---|---|---|
| `brain` | `choice`（53 択） | いま頭をいちばん占めている考えはどれか。選択肢は 53 字、説明は字ごとの英文 |
| 字の id ごとに 53 問 | `noul` | この字は、いま話し手の頭にあるか |
| `too_thin` | `noul` | 字幕が短すぎて判断できないか |

構成比は `0.5 × choice の分布 + 0.5 × 正規化(noul⁴)`。

- `choice` だけだと 1 字に寄りすぎる（実測で 0.6〜0.98）。眠い話で「休」「癒」が 0 になる
- `noul` だけだと平たすぎる。無関係な字にも 0.03〜0.3 が返るので、正規化すると最多の字でも 10% 前後にしかならない
- `noul` を 4 乗すると、0.9 台の字が 3 割前後、0.5 台の字が数 %、それ以下はほぼ消える。これと `choice` を半々で混ぜると、主役が 5〜7 割を占めて脇役が散る、本家らしい比率になる
- `too_thin` が 0.5 を超えるぶんだけ、新しい答えの重みを下げる。相づちだけで脳内が入れ替わらない

前回の構成比は Jev に送らない。送ると自分の答えに引きずられるので、ならしはコード側だけで行う。

### 字

`src/kanji.js` の 53 字。本家で出る字の報告のうち、複数の出典で一致するものを採った。

  （[知恵袋 1](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q1412303824)、[知恵袋 2](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q1231217632) の 1〜40、[作者インタビュー](https://www.j-cast.com/2007/08/07010083.html?p=all)の「40 種類」）
- 41〜53: 犬 猫 私 国 酒 謎 淫 負 金 眠 迷 善 芸（知恵袋 2 の 41〜53）

色は本家と同じく 1 字 1 色で固定。金 `#ffff00`、嘘 `#ff0000`、Ｈ `#ff25f5`、欲 `#6835ff`、愛 `#ff9eb3`、酒 `#e1df3d`、食 `#b5e600`、休 `#f7f7f7`、家 `#cff4ff`、悪 `#000000` の 10 字は本家の生成画像から測った値。残りは推定で、`kanji.js` の `measured` で区別している。推定の色は、脳の背景とのコントラスト比が 2 前後になるよう明るさを調整してある。

### 音声認識

Apple の `SpeechAnalyzer` + `SpeechTranscriber`（`ja_JP`、`progressiveTranscription`）を使う。無料で、音声は Mac の外へ出ない。

Whisper 系を採らなかったのは、無音のあいだに「ご視聴ありがとうございました」のような文を作り出すことがあるため。ここでは字幕がそのまま Jev の入力になるので、黙っているだけで脳内が汚れてしまう。

認識エンジンを替えるときは、同じ形の JSONL を stdout に出すコマンドを `STT_CMD` に指定する。

```sh
STT_CMD="node sim/fake-stt.js" npm start   # 台本を流す偽の認識器。マイクなしで画面を確かめられる
```

## 検証

```sh
npm test        # node:test。25 件
npm run probe   # 実 API。聞き方ごとに、期待の字が上位 3 字に入るかを見る
npm run sim     # 実 API。台本の会話を画面と同じ手順で流す
stt/.build/release/stt --file a.aiff   # 音声ファイルで認識だけを確かめる
```

実測（2026-09-18、`typesafe/jev-1.13`、Apple M5）:

| 項目 | 結果 |
|---|---|
| 聞き方の比較（7 文） | `choice` 53 択、`noul` 53 問、合成のどれも、期待の字が上位 3 字に 7/7 |
| 会話の通し（6 発話） | 直後に最多の字が期待どおり 5/6。外れた 1 回は「金欠だからお弁当で我慢」で、食 34・金 24 |
| Jev の応答時間 | 中央値 269ms、最大 800ms（55 問） |
| 費用 | 1 回あたり約 $0.00017（入力 約 4,000 トークン）。1 秒おきに聞き続けて 1 時間で $0.6 前後 |
| 音声認識 | 合成音声の 3 文で誤りは 1 か所（「すいたなあ」→「すいたのは」）。無音の 6 秒間は何も出さなかった |

話し声での認識精度と、発話から字幕までの遅延は、まだ測っていない。

## 画面

- 左: 脳内。300×340 の論理座標で描き、1.5 倍で見せる。配色と寸法は本家の生成画像を測った値（肌 `#ffcc99`、枠 `#5bad00`、字は 14px のゴシック）。脳の背景だけは、字を読みやすくするため本家の `#a97d7a` より薄い `#cbb1af` にしている。明るい色の字はこの背景に溶けるので、濃い色の細い縁取りを付けている（字の色そのものは変えていない）
- 右上: 字幕。確定は白、認識途中は灰色の斜体。いまの脳内のもとになった範囲に下線が付く。下線は最新の字幕ではなく、採用した答えを聞いたときに渡した範囲に付く
- ◆ Jev の判断: いまの脳内の構成比と、Jev が返した生の値（c = `choice`、n = `noul`）
- ◇ コードの事実: 応答時間、送った字幕の文字数、問いの数、呼び出し回数、累計費用
- Jev に送った `state` の生 JSON

## ファイル

```
index.html  style.css
server.js             静的配信、Jev の中継、字幕の SSE、音声認識プロセスの起動と再起動
stt/                  音声認識の Swift CLI（SpeechAnalyzer）
src/kanji.js          53 字と色と、Jev に渡す説明文
src/jev.js            Jev の呼び出し。1.2 秒返らなければ同じ要求をもう 1 本投げ、先に届いたほうを採る
src/ask.js            state と質問の組み立て、答え → 構成比
src/transcript.js     字幕の置き場と、Jev に渡す窓
src/composition.js    ならし、個数化、セルへの割り当て
src/brain.js          横顔と脳の輪郭、セルの座標
src/sketch.js         p5 の描画
src/main.js           字幕の受信、聞くタイミング、字幕と内訳の表示
sim/probe.js          聞き方の比較（実 API）
sim/live.js           会話の通し検証（実 API）
sim/fake-stt.js       台本を流す偽の認識器
test/                 node:test
```

`src/` のうち `sketch.js` と `main.js` 以外は DOM に依存せず、Node からそのまま使える。
